MITRA Project: Git & GitHub Workflow

Handwritten Engineering Flow & Branching Protocol (Ashwini & Raj)
GitHub: https://github.com/praj33/MITRA.git
★ THE GOLDEN RULE ★
MY WORK → master1 → GIT PUSH → RAJ REVIEWS → MERGE → main
👩‍💻 Ashwini's Domain master1

• Ashwini creates, modifies, and commits all feature & backend code ONLY on the master1 branch.

• Never push directly to main.

• All daily commits & pushes go to origin master1.

👨‍💻 Raj's Domain main

• Raj is the Repository Owner & maintainer of main.

• Raj reviews PRs / commits from master1, runs staging tests, and performs the merge into main.

• main represents the single source of truth / production runtime.

✏️ Visual Git & GitHub Branching Architecture
git push origin master1
📋 Complete Step-by-Step Execution Guide
  • 1
    Clone the Repository:
    git clone https://github.com/praj33/MITRA.git
    cd MITRA-Universal-Companion
  • 2
    Switch to your dedicated development branch (master1):
    git switch master1
    👉 Check active branch anytime with: git branch (The star * master1 indicates you are safe on your branch).
  • 3
    Work & Commit Local Changes:
    # 1. Check modified files
    git status

    # 2. Stage changes
    git add .

    # 3. Commit with clear message
    git commit -m "feat: update companion chatbot UI and API bridge"
  • 4
    Push changes to GitHub (Only to master1):
    git push origin master1

    🛑 Important: Ashwini's changes go to master1, NOT directly to main!

  • 5
    Raj's Review and Final Merge:

    1. Local master1 pushes to GitHub origin/master1.

    2. Raj inspects the code, runs validation tests on staging.

    3. Raj merges master1 → main.

    4. After merge, main contains the approved production changes.

  • 6
    Updating / Syncing your master1 with latest main:

    When Raj adds new features or updates on main, sync your local master1 branch:

    git switch main
    git pull origin main
    git switch master1
    git merge main

    # If any conflicts occur, resolve them, test, then:
    git push origin master1

⚠️ STRICT SAFETY RULES (MANDATORY)
  • 1. NEVER push directly to main: Raj alone decides when code enters main.
  • 2. NEVER use git push --force: Force pushing overwrites commits and causes lost work.
  • 3. ALWAYS develop on master1: Verify branch with git branch before editing.
  • 4. Push completed work only to master1: git push origin master1.
  • 5. Keep master1 synchronized: Merge latest main into master1 before starting major new milestones.
  • 6. Raj reviews & merges: Ashwini pushes → Raj reviews → Raj merges to main.
